1. СЕРВЕР -> ФРОНТ

1.1 Получение списка растений

GET /api/plants

GET /api/plants?status=unhealthy

Ответ при status=unhealthy:
{
    "plants": [
        {
            "plant_id": 1,
            "shelf_id": 1,
            "status": "unhealthy",
            "issues": "pH too low (5.0)",
            "last_update": "2026-04-02T12:00:01"
        }
    ]
}

\\status=all или без параметра:
{
    "plants": [
        {
            "plant_id": 1,
            "shelf_id": 1,
            "status": "healthy",
            "issues": null,
            "last_update": "2026-04-02T12:00:01"
        },
        {
            "plant_id": 2,
            "shelf_id": 1,
            "status": "unhealthy",
            "issues": "pH too low (5.0)",
            "last_update": "2026-04-02T12:00:01"
        }
    ]
}

\\status=healthy:
{
    "plants": [
        {
            "plant_id": 1,
            "shelf_id": 1,
            "status": "healthy",
            "issues": null,
            "last_update": "2026-04-02T12:00:01"
        }
    ]
}

\\status=invalid (ошибка):
{
    "error": "Invalid status value. Allowed: all, healthy, unhealthy"
}

\\растений нет:
{
    "plants": []
}

\\ошибка сервера:
{
    "error": "Internal server error"
}

1.3 Получение истории показаний

GET /api/readings

Параметры запроса:
- plant_id (обязательно) - ID растения: 1, 2, 3...
- limit (необязательно) - количество записей: 1-1000 (по умолчанию 100)
- from_date (необязательно) - начальная дата: ISO формат
- to_date (необязательно) - конечная дата: ISO формат

Пример запроса:
GET /api/readings?plant_id=1&limit=10&from_date=2026-04-01T00:00:00

Ответ:
{
    "readings": [
        {
            "id": 1,
            "plant_id": 1,
            "shelf_id": 1,
            "ph": 6.5,
            "temperature": 23.5,
            "humidity": 65,
            "light": 1,
            "water_level": 80,
            "moisture": 40,
            "diagnosis": "healthy",
            "confidence": 0.95,
            "image_url": "/uploads/photo_001.jpg",
            "created_at": "2026-04-02T12:00:01"
        }
    ]
}

\\без limit (по умолчанию 100 записей):
GET /api/readings?plant_id=1
(ответ аналогичен, но с 100 записями)

\\с to_date:
GET /api/readings?plant_id=1&to_date=2026-04-02T23:59:59
(возвращает записи только до указанной даты)

\\нет показаний:
{
    "readings": []
}

\\не указан plant_id:
{
    "error": "plant_id is required"
}

\\растение не найдено:
{
    "error": "Plant not found"
}

\\диагноз unhealthy:
{
    "readings": [
        {
            "id": 2,
            "plant_id": 1,
            "shelf_id": 1,
            "ph": 5.0,
            "temperature": 23.5,
            "humidity": 65,
            "light": 1,
            "water_level": 80,
            "moisture": 40,
            "diagnosis": "unhealthy",
            "confidence": 0.87,
            "image_url": "/uploads/photo_002.jpg",
            "created_at": "2026-04-02T13:00:01"
        }
    ]
}

\\ошибка сервера:
{
    "error": "Internal server error"
}



2. ФРОНТ -> СЕРВЕР


2.1 Управление поливом

POST /api/command/water

Пример запроса (включить полив):
{
    "state": "1"
}

Ответ при state=1:
{
    "status": "ok",
    "message": "Watering started",
    "state": "on"
}

\\state=0 (выключить полив):
Запрос:
{
    "state": "0"
}
Ответ:
{
    "status": "ok",
    "message": "Watering stopped",
    "state": "off"
}

\\неверный state:
Запрос:
{
    "state": "2"
}
Ответ:
{
    "error": "Invalid state. Use 1 or 0"
}

\\нет поля state:
Запрос:
{}
Ответ:
{
    "error": "state is required"
}

\\ошибка отправки на ESP:
{
    "error": "Failed to send command"
}
